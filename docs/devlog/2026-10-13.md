## 구현

`space_app.py`의 `TABLE_CSS`에 CSS `:has()` 규칙 3개를 추가했다:
`.prose table tr:has(.rn-must/.rn-check/.rn-reference) td:first-child { border-left: ...색상 }`.
각 검증 행(row)은 이미 `render()`가 심어둔 `<span class="rn-badge rn-must|rn-check|rn-reference">`
배지를 담고 있으므로, `:has()`로 그 배지를 가진 행을 골라 왼쪽에 두꺼운 색깔 테두리(must=빨강,
confirm=주황, reference=회색)를 긋는다. `render()` 함수 자체는 한 글자도 바꾸지 않았으므로
표 구조에 의존하는 기존 테스트(예: 한 행 = 3셀/4파이프)에 영향이 없고, Gradio 렌더 결과가
변경 전과 바이트까지 동일한지 보는 `check_english_unchanged`도 그대로 통과했다 — 10-06
모바일 표 CSS 수정과 같은 패턴(순수 CSS, 로직 무변경)이다.

사전 설치된 Chromium(Playwright, `/opt/pw-browsers`, 네트워크 다운로드 없음)으로 로컬 부팅한
데모를 실제로 조작해 확인했다: 1280px에서 LED 리어램프 예시를 리뷰하면 Must review의 두
행과 Confirm의 일곱 행 모두 왼쪽에 빨강/주황 테두리가 선명하게 보인다(스크린샷 확인).
390px(모바일)에서도 `document.documentElement.scrollWidth === clientWidth`(390)로 페이지
전체 가로 스크롤이 없고, 콘솔/페이지 에러도 없었다.

`scripts/test_dryrun.py`의 `check_mobile_table_css`에 새 CSS 규칙 3개(`rn-must`/`rn-check`/
`rn-reference` 각각의 `tr:has(...) td:first-child { border-left: ... }`)가 `TABLE_CSS`에
있는지 확인하는 단언을 추가했다.
