## 구현

범위를 안전하게 좁혔다: `scripts/test_dryrun.py`의 `check_korean_scope_display`가 판정 표의
각 행이 정확히 3칸(파이프 4개)짜리 마크다운 표 행이라는 것을 그대로 단언하고 있어, 표 구조를
통째로 카드 레이아웃으로 바꾸는 것은 이번 시간 예산에 비해 위험이 컸다. 대신:

- `space_app.py`의 `render()`: 각 판정 행의 "적용 여부·신뢰도" 칸을 우선순위별 색상 배지
  (`<span class="rn-badge rn-must|rn-check|rn-reference">`, 빨강/주황/회색, 기존에 쓰던
  `TABLE_CSS` 문자열에 CSS 추가)로 감쌌고, 각 우선순위 제목 앞에 같은 색의 이모지
  (🔴/🟠/⚪)를 붙였다. 표 하나의 "Must review" 제목에서만 색을 보여주던 것을, 그 아래 모든
  행에서도 한 번씩 더 보여줘 스캔하기 쉽게 했다.
- 실제로 색 배지로 렌더링되는지 직접 확인했다(추측하지 않음): 먼저 Playwright로 테스트해보니
  Gradio `Markdown` 컴포넌트 안에 블록 레벨 `<div>`를 넣으면 그 블록의 마크다운 링크 문법이
  파싱되지 않고 `[link](url)` 그대로 글자로 나온다는 걸 확인했다(그래서 표 행 전체를 카드
  `<div>`로 바꾸는 접근은 포기). 반면 표 칸 안의 인라인 `<span>`은 기존에도 `<br>` +
  `[text](url)` 조합이 잘 작동했던 것처럼 이번에도 markdown 링크와 함께 정상 동작한다.
  헤드리스 Chromium(사전 설치된 Playwright)으로 1280px 라이트, 1280px 다크
  (`?__theme=dark`), 390px(모바일)에서 스크린샷 확인: 배지가 실제로 색이 있는 알약 모양으로
  보이고 두 테마 모두 대비가 충분하며, 모바일에서 페이지 전체 가로 스크롤은 생기지 않았다.
