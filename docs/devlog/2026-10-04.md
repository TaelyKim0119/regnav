## 오늘 한 개선과 이유

Claude 담당 일정 중 10-06 "KMVSS article numbers"가 오늘(10-04) 기준 3일 이내지만, 로드맵에
적힌 대로 남은 조각(자동차용 전자파 조문)은 법제처 Open API 키(오너 전용 가입)와 일반 웹
접속(이 샌드박스에서 차단) 둘 다 필요해 이번에도 진행 불가 — 여전히 막혀 있음만 확인했다.
그래서 백로그 3번 "Accuracy"를 이어서 봤다. 어제 devlog의 "다음 단계"에 "must-review
recall(56%)은 `regnav/judge.py`의 드라이런 confidence->priority 고정 임계값 문제를 다음에
본다"고 명시돼 있었다.

조사해 보니 실제로는 임계값 문제가 아니라 어제 고친 것과 같은 "어휘 격차"가 한 겹 더
있었다. `regnav/judge.py`의 `_dry()`(드라이런 자리표시 판정)는 파트 단어를 해당 규정의
*실제* 제목·Scope 본문과 직접 대조하는데, 이때 쓰는 `terms(part)`는 `fmvss_candidates()`가
이미 쓰고 있는 `US_TERMS` 동의어 치환(`regnav/text.py`, tyre->tire, wheel->rim,
glass/windscreen/windshield->glazing)을 거치지 않는다. 그래서 "glass windscreen"이라는
파트 설명이 UN R43의 실제 OJ Scope 원문("safety glazing materials ... windscreens ...
glass-plastics")과 대조될 때 title_hits=1, scope_hits=1(score=3, conf=0.70)에 그쳐 "must"
컷오프(>=0.8, score>=4)를 못 넘겼다 — 어제 candidate 검색에서 고친 것과 완전히 같은
용어 문제가 판정 점수 쪽에도 남아 있었던 것이다.

고친 내용: `_dry()`에서 `words = terms(part)` 대신 `words = us_terms(terms(part))`를 쓰도록
한 줄 변경(`regnav/judge.py`). 임계값(>=0.8/>=0.5)은 전혀 건드리지 않았고, 이미 있던 동의어
테이블을 후보 검색뿐 아니라 점수 매기기에도 똑같이 적용한 것뿐이라 특정 테스트 파트에 맞춘
역산이 아니다(tyre/wheel/glass 계열 파트에만 영향, 다른 파트는 무관).
