## 구현

`space_app.py`의 `TABLE_CSS`에 세 줄을 추가/수정했다: 기존 `tr:has(.rn-must/.rn-check/
.rn-reference) td:first-child { border-left: ... }` 규칙에 `border-radius: 6px 0 0 6px`를
더하고, `td:last-child`에 반대쪽 모서리를 둥글게 하는 규칙을 추가했으며, 표 전체에
`.prose table { border-collapse: separate; border-spacing: 0 6px; }`를 추가했다.
`border-collapse: separate`가 없으면 이웃 행의 테두리가 서로 합쳐져 `border-spacing`도
모서리 둥글림도 전혀 적용되지 않으므로 이 한 줄이 핵심이다. `render()` 함수는 한 글자도
바꾸지 않았다(배지 `<span>`이 이미 있으므로 `:has()`로 그 행을 고르는 것은 10-13 슬라이스와
동일한 방식) — 그래서 `scripts/fixtures/english_outputs_baseline.json`도 다시 만들 필요가
없었고 `check_english_unchanged`가 그대로 통과했다.

사전 설치된 Chromium(Playwright)으로 로컬 부팅한 데모를 1280px 라이트, 1280px 다크
(`?__theme=dark`), 390px 모바일에서 실제로 확인했다. CSS가 소스에 존재하는지뿐 아니라
`getComputedStyle`로 Must review 행의 첫 번째 셀이 실제로 `border-collapse: separate`,
`border-spacing: 0px 6px`, `border-radius: 6px 0px 0px 6px`를 받는지 직접 확인했다(선언만
있고 적용되지 않는 CSS 버그를 피하기 위해). 세 화면 모두 콘솔/페이지 에러 없음,
390px에서 `document.documentElement.scrollWidth === clientWidth`(390)로 페이지 전체 가로
스크롤 없음을 재확인. `.rn-*` 배지가 없는 비교표·조문 비교표도 같은 행 간격을 받는데
스크린샷으로 보면 어색하지 않고 오히려 여유 있어 보인다.

`scripts/test_dryrun.py`의 `check_mobile_table_css`에 `border-collapse: separate`,
`border-spacing:`, 그리고 각 `.rn-*` 행의 `td:first-child`/`td:last-child` 양쪽에
`border-radius:`가 있는지 보는 단언을 추가했다.
