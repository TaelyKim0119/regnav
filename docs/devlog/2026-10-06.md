## 오늘 한 개선과 이유

Claude 담당 일정 중 10-06 "KMVSS article numbers"가 오늘 마감이지만 `regnav/sources/kmvss.py`를
재확인한 결과 어제와 동일하게 법제처 Open API 키(오너 전용 가입)와 일반 웹 접속(이 샌드박스에서
차단) 둘 다 없어 자동차용 전자파(EMC) 조문을 채울 수 없다 — 다시 막혀 있음만 확인했다(로드맵에
확인 날짜 10-06 추가).

그래서 백로그 4번 "Gradio 데모 디자인"을 이어서 진행했다. 어제 devlog의 "다음 단계"에 "다음
실행에서 헤드리스 브라우저 스크린샷 시도를 검토"라고 적어뒀던 바로 그 작업이다. 이 샌드박스에는
Playwright용 Chromium 바이너리가 이미 설치되어 있어(`/opt/pw-browsers`, 다운로드 없음)
`pip install playwright`만으로 실제 렌더링 화면을 볼 수 있었다.

데스크톱(1280px)은 문제없었지만, 모바일 폭(390px)에서 스크린샷을 찍어보니 판정 표·비교표·
특히 조문 비교표(열이 5~6개)에서 "Number" 같은 평범한 단어가 "N/u/m/b/e/r"처럼 한 글자씩
세로로 쪼개져 거의 읽을 수 없는 상태였다. 원인은 Gradio 6의 Markdown CSS가 긴 URL이 페이지를
넘치지 않게 하려고 `overflow-wrap: break-word`를 깔아두는데, 그게 표 셀에도 상속되어 390px에
맞추려는 자동 표 레이아웃이 열 폭을 극도로 좁히면서 단어를 글자 단위로 쪼갰기 때문이다. 심사위원이
휴대폰으로 데모 링크를 처음 열어볼 수 있다는 점에서 실제 체감 품질에 영향을 주는 문제라 이번
실행 범위로 선택했다.

## 구현

`space_app.py`에 `TABLE_CSS` 상수를 추가하고 `demo.launch(css=TABLE_CSS)`로 전달(Gradio 6부터
`css`가 `Blocks()` 생성자가 아니라 `launch()`로 이동했음을 확인). 표 안에서는 정상적인 단어
단위 줄바꿈을 복원하고(`overflow-wrap: normal; word-break: normal`), 그래도 폭이 넘치면 그
표가 속한 `.prose` 블록만 가로 스크롤되게 했다(`overflow-x: auto`). 재스크린샷 + Playwright로
`scrollWidth`를 확인해, 조문 비교표가 든 `.prose` 블록 하나만 스크롤되고 페이지 전체 폭은
390px로 그대로임을 확인했다. `scripts/make_space.py`의 Space 계약 검사가 소스 문자열
`"demo.launch()"`를 리터럴로 찾고 있어서(이제는 `demo.launch(css=TABLE_CSS)`) `"demo.launch("`로
완화했다(의도는 동일: launch가 실제로 호출되는지). `scripts/test_dryrun.py`에 `check_mobile_table_css`를
추가해 `TABLE_CSS`의 세 속성과 `demo.launch`에 실제로 전달되는지를 오프라인으로 검증(브라우저
스크린샷 자체는 자동화 스위트에 넣지 않음 — `playwright`는 `requirements.txt`에 없는 일회성
진단 도구로만 사용).
